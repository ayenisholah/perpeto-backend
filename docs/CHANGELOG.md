Owner-only `pilot` endpoints grant eligibility (when a connection is preflight-`ELIGIBLE`), arm a route with a one-use passkey `ActionProof` (`ArmPilot`) plus a typed alias confirmation, and disarm (always available; halts new risk). Transitions emit outbox events. Control-plane only — LIVE stays fail-closed, so arming records intent and changes no execution. OpenAPI/client **0.18.0** (vendored into mobile) plus a flag-gated mobile Pilot card. Platform route certification, `permission_version` session invalidation, hash-chained audit, and Slice 8 live execution remain deferred.

The `venue-credentials` start/finish endpoints verify the proof before any secret operation, take write-only credentials that are never logged or returned, and are 503 in PAPER. OpenAPI/client **0.17.0** (vendored into mobile) plus a flag-gated mobile enrollment form. The live preflight worker, credential deletion, and the rewrap job remain deferred; `venue-admin` stays transitional/dev tooling.

### Security

- Staging deployment validates paper mode and uses a pinned SSH host key; runtime trading secrets remain outside GitHub Actions.
- Provider identity is keyed by immutable subject rather than email; access is pending by default, refresh credentials are device-bound/rotating, and retained deletion evidence uses an audit pseudonym.

### Fixed

- Repaired the known connector build errors by retaining borrowed Bybit/OKX JSON values and giving exact-decimal `PriceLevel` values equality semantics required by `BookView`.

- Expanded shared-document drift coverage to the new architecture/key-management sources and made documentation validation ignore nested dependency/cache directories.

- Applied canonical Rust formatting and completed the M0 OpenAPI metadata, response, and explicit public-health security declarations required by contract linting.

### Changed

- Updated repository status and runtime examples to describe the implemented M2/M3 safety modes and the remaining WebSocket and credentialed certification gates without implying live readiness.

The Apple audience `com.signex.mobile` and the `signex://` OAuth redirect scheme are unchanged. Deployments must update `runtime.env` (new variable names, `DATABASE_URL`) and rename the database in lockstep — see `docs/DEPLOYMENT.md`.
- Moved project-control documentation under `docs/` and recorded the temporary solo-maintainer administrator bypass policy.
- Hardened the versioned API client to reject incompatible health payloads and verify compiled code and schemas before publication.
