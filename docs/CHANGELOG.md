## [Unreleased]

### Added

- M4 key intake (testnet and demo only).
  - **Secrets:** the CDK `Perpeto-Staging` stack creates empty `perpeto/sandbox/{BYBIT,BINANCE_SPOT,BINANCE_PERP,OKX}` secrets, which the host may read, and `perpeto/sandbox/KEYS` for the sandbox AES master key, which the host also writes.
  - **`scripts/aws/put-sandbox-key.sh`:** the operator stores each key from their own terminal. Values are read without echo and sent on stdin, never in argv, a file, the repository or a chat. Only the last four characters of the key are printed.

- M2 and M3 are closed (2026-11-25).
  - **M2 evidence:** `docs/evidence/m2/PUBLIC_PROBE.md` (all three venues pass the keyless probe from staging) and `docs/evidence/m2/STAGING_SOAK.md` (24 hours on staging, from CloudWatch).

  - **README:** an architecture diagram, an evidence index, and M2/M3 marked done.
  - **Status docs:** `MILESTONE` (shared version 9), `IMPLEMENTATION`, `TRACEABILITY` and `PROGRESS` are updated; M4 is next.

- M3: one-command local start. `docker compose up --build` from the repository root runs PostgreSQL, Redis, migrations, the API, the live-data PAPER engine and the `perpeto-web` platform.
  - **Keys:** a one-shot `keys` service generates this machine's access-token, MFA and web-session keys into a volume, so nothing secret is committed.
  - **Demo and sign-in:** the demo and the development sign-in are on, and the web platform answers at <http://localhost:3000>.
  - **Hardening:** every application container runs read-only, without capabilities, and only on `127.0.0.1` ports.
  - **README:** the 5-minute tour now leads with the live demo and the local start.

- M3: backend support for web sign-in through the Next.js platform (DEC-0021), with OpenAPI and `@ayenisholah/perpeto-api-client` **0.25.0** (additive).
  - **Web devices:** `exchange` accepts `platform: WEB` and stores the platform it receives; it used to hardcode `IOS`. Any other platform is still refused.
  - **Nonce on the web:** a WEB exchange must bind the challenge nonce for Google as well as Apple. Google Identity Services carries it on the web, and the Google verifier now returns the claim. Native Google sign-in still relies on PKCE and the one-use challenge.
  - **Apple on the web:** `PERPETO_APPLE_WEB_SERVICES_ID` adds the web Services ID to the accepted Apple audiences, next to the bundle ID.
  - **Development sign-in:** the PAPER-only dev verifier accepts an optional third part, `perpeto-dev:<subject>:<email>:<nonce>`, so local web development can satisfy the web nonce binding.
  - **Immediate revocation:** the bearer middleware now refuses an access token whose session is no longer active or has expired (401 `SESSION_REVOKED`). Logout, session revocation and reuse detection used to take effect only when the 15-minute token lapsed.
  - **Tests:** a web exchange rejecting a wrong nonce and recording a `WEB` device, an unknown platform rejected, and a logged-out token refused on its next request.

- M3: the staging host serves the Next.js web platform from `perpeto-web` (DEC-0021).
  - **Caddy:** a second site, `PERPETO_APP_HOSTS` (`app.perpeto.xyz` and `app.<elastic-ip>.sslip.io`), sends every request to the `web` container on port 3000, with HSTS, `nosniff`, referrer and framing headers. The browser never reaches the API directly.
  - **Compose:** `web` runs the `perpeto-web` image read-only, without capabilities, behind the `web` profile, with tmpfs for `/tmp` and the Next.js cache. It waits for a healthy API.
  - **Configuration:** `refresh.sh` derives the app hosts, keeps the last rolled-out web image, enables the profile only when that image can be pulled, generates `PERPETO_WEB_SESSION_KEY` once, and renders a separate `web.env` holding only what the web server needs. `staging.env` turns on `PERPETO_DEMO_ENABLED` and adds an empty `PERPETO_APPLE_WEB_SERVICES_ID`.
  - **Web deploys:** `deploy/ec2/update-web.sh` recreates only the `web` container. The CDK `Perpeto-Deployer` stack adds the `Perpeto-UpdateWeb` SSM document, whose only parameter must match `ghcr.io/ayenisholah/perpeto-web:sha-<full sha>`, and the `perpeto-web-deployer` IAM user, which may only send that document to the staging host. `create-deploy-key.sh` now takes a user, repository and environment.
  - **CI:** the `infra` job validates the compose files under each profile and the Caddyfile.

- M3: the read-only demo viewer (DEC-0017), with OpenAPI and `@ayenisholah/perpeto-api-client` **0.24.0** (additive).
  - **Principal:** migration `0020_demo_viewer.sql` adds `users.demo`, allows at most one demo user, and lets devices be `WEB`. With `PERPETO_DEMO_ENABLED=true`, which only PAPER permits, the API seeds one demo tenant whose user holds only `VIEWER`, plus one enabled paper strategy (BTC and ETH across Binance, Bybit and OKX), so the engine trades it and the read models fill.
  - **Sessions:** `POST /api/v1/demo/session` issues an access-only session that lasts as long as its 15-minute access token. It returns no refresh token, deletes expired demo sessions as it goes, and is capped at 120 sessions a minute per deployment (429 `DEMO_RATE_LIMITED`). It returns 404 when the demo is off.
  - **Read-only guard:** `require_auth` refuses every non-GET request from the demo principal with 403 `DEMO_READ_ONLY` before any handler runs. This also covers routes whose handlers only check that the account is active, such as alert acknowledgement, passkeys, session revocation and account deletion.
  - **`/auth/me`:** gains `demo`; the client also adds `createDemoSession()`.
  - **Client fix:** `PerpetoClient` called the global `fetch` as `this.#fetch(...)`, which browsers reject with "Illegal invocation". React Native tolerated it, so it surfaced only with the hosted web build. The default is now an unbound wrapper, and a test fails if `fetch` runs with any `this`.
  - **Tests:** the first router-level tests (`bins/api/src/router_tests.rs`). They read every route from `routes.rs`, so a new route is covered automatically. It asserts all 43 protected mutations return 403 for the demo, the demo reads its ten surfaces with 200 and sees its enabled strategy, and the endpoint is absent when disabled. The same harness closes an M2 evidence gap: an owner's `POST /positions` against a stored snapshot older than `PERPETO_MAX_SNAPSHOT_AGE_SECS` returns 409 `STALE_MARKET_DATA`.

- PAPER staging runs on AWS (DEC-0020). The CDK app in `infra/` (`Perpeto-Staging`, `Perpeto-Deployer`) owns one `t3.small` in `eu-north-1` on a pinned Amazon Linux 2023 AMI, with an Elastic IP, a public-only VPC open on 80/443 only, Secrets Manager for every secret, CloudWatch Logs for every container, daily AWS Backup snapshots and automatic recovery.

  - `deploy/ec2/refresh.sh` deploys one image on the host: it fetches the deployment files at the exact commit, renders `runtime.env` from Secrets Manager, and generates the application keys and the one-use deployment token on first run.
  - `scripts/deploy-staging.sh` accepts an optional compose override (`PERPETO_COMPOSE_OVERRIDE`) and can provision the database roles and their passwords idempotently (`PERPETO_PROVISION_DB_ROLES=1`).
  - `scripts/aws/deploy-host.sh` drives a deploy through SSM Run Command and checks `/readyz` from outside; `scripts/aws/create-deploy-key.sh` creates or rotates the deployer key straight into the GitHub `staging` environment.

- M2 step 4: the feed-freshness contract (OpenAPI and `@ayenisholah/perpeto-api-client` **0.23.0**, additive).
  - **`/health` venues:** each venue gains `feed_status` (`HEALTHY`, `DEGRADED`, `UNAVAILABLE` or `UNKNOWN`), `last_observed_at` and `feed_error`. These are derived by `venue_health` from the latest stored market snapshot, with fixture snapshots judged by their legs.
  - **Real values instead of fabricated ones:** `market_data_age_seconds` is now real; it was hardcoded to `0`. `connected` reflects whether the snapshot reached the venue; it used to be `true` unless a breaker was active. `status` is `DEGRADED` for an active breaker or an unhealthy feed.
  - **Opportunity legs:** gain an optional `observed_at`, taken from the forecast input. Payloads stored before this change still decode.
  - **Tests:** 6 health-derivation tests, a legacy-payload decode test, and a client contract test for the new fields.

- M2 step 3: paper trading runs on the market snapshot.
  - **Engine:** takes one snapshot per tick and uses it for venue breakers, supervision, ranking, persistence and auto-entry. `PERPETO_PAPER_SOURCE=live` (the default) uses keyless public data on wall-clock time; `fixtures` keeps the deterministic replay. Unhealthy venue feeds are logged every scan.
  - **`ExecutionService::open_from` / `supervise_with`:** take a snapshot. Each leg fills at the VWAP of its captured book (`book_fill_price`, contract-multiplier aware), and books too thin for the size are refused with `InsufficientDepth`. The fixture `open` and `supervise` wrap them unchanged, and a test proves identical fills.
  - **API:** `POST /positions` opens against the stored snapshot and refuses it once it is older than `PERPETO_MAX_SNAPSHOT_AGE_SECS` (default 90). New 409 codes: `STALE_MARKET_DATA`, `VENUE_DEGRADED` and `INSUFFICIENT_DEPTH`.

- M2 step 2: persist the market snapshot behind each scan.
  - **Schema:** migration `0019_market_snapshots.sql` adds a nullable `scan_runs.market_snapshot` column. `scan_runs` stays platform-scoped because it holds public market data only.
  - **Repository:** `ScannerRepo::record_scan_with_snapshot` writes the scan, its opportunities and the snapshot in one transaction. `ScannerRepo::latest_snapshot` returns the newest stored snapshot with its wall-clock `created_at`, which is the staleness basis because `scanned_at` is simulated in fixture mode. Scans stored without a snapshot are skipped.
  - **Types:** the snapshot types (`MarketSnapshot`, `LegBook`, `BookSide`, `FeedStatus`, `VenueFeedStatus`) moved to `scanner-service::market`, which owns the market data model. `venue-service` re-exports them unchanged.
  - **Persisted form:** `MarketSnapshotDto` serializes decimals as strings, so the round trip is exact.
  - **Tests:** 4 unit tests (exact JSON round trip beyond f64 precision, rejection of unknown enumerations, book lookup, fixture snapshots) and 2 `DATABASE_URL`-gated PostgreSQL tests (exact round trip, and latest-wins ignoring snapshot-less scans).

- M2 step 1: a keyless public market source (DEC-0016).
  - **Source:** `crates/venue-service/src/public_market.rs` adds `PublicMarketSource`. It builds Binance, Bybit and OKX connectors with no credentials and reads health, instruments, order books and funding for the configured underlyings (`BTC,ETH` by default).
  - **Failure handling:** a venue that errors, times out or returns a crossed book is reported `UNAVAILABLE` and contributes no legs. Other venues continue, and there is no fixture fallback.
  - **Caching:** instrument metadata is cached per venue for 15 minutes, with a 45-second timeout. Books and funding use a 10-second timeout and are read fresh on every snapshot.
  - **Shared measurement:** the engine's credentialed SANDBOX/SHADOW scan now measures legs through the same `measure_leg`, which also gives it timeouts it previously lacked.
  - **Evidence CLI:** `funding-arb-connector-evidence snapshot` prints one live snapshot. The first live run is recorded in `docs/evidence/m2/PUBLIC_SNAPSHOT.md`.
  - **Tests:** 12 tests use a scripted `FakeConnector`. They cover the universe filter, funding on perpetuals only, book capture, degraded health, failure isolation, timeout, crossed book, metadata caching, configuration parsing, and a source-level guard that the module never references the credential store or registry.

- M4 audit review endpoint — an owner-only `GET /api/v1/audit` returns the tenant's hash-chained control-plane events (pseudonymized actor, non-secret details, chained `event_hash` in hex) together with an `intact` flag computed by `verify_audit_chain`, completing the audit feature (write → read/verify). Exposes only display-safe fields — never `previous_hash`, session, or request internals. OpenAPI/client **0.22.0** (vendored into mobile) plus a flag-gated read-only "Recent activity" card. A `DATABASE_URL`-gated test asserts the listing returns events newest-first and that `intact` flips to `false` after tampering.

- M4 hash-chained audit log — every sensitive control-plane action (credential enroll/rotate/revoke/delete, pilot arm/disarm, route certify) now appends a tamper-evident row to the pre-existing `audit_events` table (`event_hash = SHA-256(previous_hash ‖ canonical(fields))`, length-prefixed injective encoding). A per-tenant `pg_advisory_xact_lock` serializes appends so the chain cannot fork, actors are pseudonymized (`audit_actors`), and a `verify` walk recomputes every link to detect any mutation or deletion. Append is best-effort-after-commit (a failure is logged, never dropped, and never fails the action). No migration (the schema and forced-RLS already exist) and contract-neutral — server-internal, no API/OpenAPI/client/mobile change (a read/verify endpoint is deferred). A `DATABASE_URL`-gated test proves linkage, cross-tenant isolation, and tamper detection.

- M4 ciphertext-rewrap job — a new `funding-arb-rewrap` worker (SANDBOX/SHADOW only, like the reconciler) re-encrypts every non-revoked stored credential to the secret backend's current key version on an interval, so a rotated key can be retired without replacing the exchange credential. A new `SecretStore::rewrap` primitive backs it: the Vault store uses Transit's native `rewrap` endpoint (ciphertext-only, plaintext never leaves Vault, gated on a dedicated `PERPETO_VAULT_REWRAP_TOKEN`), and the transitional AES store gains a decrypt-only keyring (`with_previous_keys`) so it can migrate rows across key versions internally. Idempotent (a secret already at the current version is a no-op); the credential and its `plaintext_digest` are unchanged. Server-internal — **no API/OpenAPI/client/mobile change**. A `DATABASE_URL`-gated test proves the AES v1→v2 migration (version advances, ciphertext changes, digest stable, load intact, second run no-op).

- M4 credential deletion — a passkey-gated owner/trader `POST /venue-credentials/{id}/delete/start`+`/finish` (bound to a new `DeleteCredential` `ActionDescriptor`) destroys every connection's stored secret, disables the connections, and tombstones the venue account, completing the enroll→rotate→revoke→**delete** lifecycle. `get` now hides tombstoned accounts (like `list`), so a deleted account 404s on every read path and deletion is idempotent. Fail-closed: 503 in PAPER, 409 while the pilot is `PILOT_ARMED` (disarm — which flattens — first), and the passkey proof is required before any secret is destroyed. Finish returns 204. OpenAPI/client **0.21.0** (vendored into mobile) plus a flagged post-enroll "Delete credential" button. A `DATABASE_URL`-gated test proves secrets are destroyed, the account is invisible, and a repeat delete is `NotFound`.

- M4 scheduled preflight worker — a new `funding-arb-preflight` worker (SANDBOX/SHADOW only, like the reconciler) re-runs preflight on an interval against every `ELIGIBLE` connection and fail-closed **demotes** any that no longer pass their config checks or live reconciliation to `PREFLIGHT_FAILED`, so `ELIGIBLE` is continuously re-validated rather than a one-time stamp before Slice 8 wires it into live execution. The preflight composition (config checks → `ReconciliationService.run` → `record_preflight_result`) is extracted into a shared `venue-service` `PreflightService`/`evaluate_config`, run identically by the API endpoint and the worker (the endpoint keeps its exact `PreflightReport` contract — **no API/OpenAPI/client/mobile change**). Promoting `PENDING_PREFLIGHT`/`PREFLIGHT_FAILED` stays operator-triggered via the endpoint; the worker only demotes on drift. Credential deletion remains the open slice-6 item.

- M4 credential preflight — an owner/trader `POST /venue-credentials/{id}/preflight` composes the connection config checks with a live `ReconciliationService.run` and calls the previously-orphaned `record_preflight_result`, so a connection can finally reach `ELIGIBLE` and the enroll→preflight→arm→gate pipeline is exercisable end-to-end. `record_preflight_result` is now re-runnable. Fail-closed (503 in PAPER; `PREFLIGHT_FAILED` unless both config and reconciliation pass; reaching `ELIGIBLE` needs testnet credentials). OpenAPI/client **0.20.0** (vendored into mobile) plus a flagged post-enroll "Run preflight" button. A scheduled preflight worker and credential deletion remain deferred.
