# Changelog

All notable repository changes are recorded here using Keep a Changelog categories.

## [Unreleased]

### Added

- M3 Slice 1 — added fail-closed `SANDBOX` and read-only `SHADOW` runtime modes plus DEC-0011: only sandbox may submit to explicitly non-production connector accounts, shadow never submits, live stays locked, and shared-v1 credentials use an audited server CLI rather than the non-step-up API.

- M3 foundation preparation — normalized the locally committed M2 Rust edits so the workspace formatting gate is clean before connector work begins; the linked Rust build remains delegated to the Linux verification environment because the local Windows host has no MSVC linker.

- M2 Slices 6–7 — immutable versioned paper strategies with stricter admission rules, fixed/percent/dynamic allocation, concurrency/cooldown and auto-compound evaluation, engine auto-entry and position attribution; portfolio/PnL aggregation, synthetic venue/service health, durable deduplicated alerts and acknowledgement; migrations `0007`–`0009`, strategy/monitoring APIs, OpenAPI/client **0.10.0**, and complete mobile Strategies/Portfolio/Health/Alerts tabs. M2 is complete.

- M2 Slice 5b — deterministic per-leg `FULL`/`PARTIAL`/`UNKNOWN` paper outcomes with reconcile-before-retry recovery, `OPENING→RECOVERING→OPEN|CLOSED`, slippage-capped completion or recovery flatten, daily-loss/drawdown limits, a degraded-venue fixture tick, durable circuit breakers and outbox events (`0006_circuit_breakers.sql`), engine breaker enforcement, and RBAC emergency-control APIs. OpenAPI/client **0.8.0** adds fill scenarios, `RECOVERING`, recovery/breaker exit reasons, controls, and breaker types; mobile adds breaker badges and halt/read-only/disable/flatten/resume controls.

- M2 Slice 5a — deterministic paper re-hedging and auto-exit. `funding-arb-domain::position` now measures signed current-mark delta, persists consecutive residual breaches, appends corrective capped-IOC hedge orders after two breached ticks, and evaluates funding-flip/threshold/venue-health exits with recorded reasons. `ExecutionService::supervise` re-marks from the scenario path and drives `t1→t2→t3`; the engine persists supervision on an accelerated configurable paper clock. Position reads expose `residual_breach_ticks` and nullable `exit_reason` through OpenAPI/client **0.7.0**. Recovery, breakers, and emergency controls remain Slice 5b.
- M2 Slice 4 — paper position close and funding capture. `funding-arb-domain::position` gains deterministic funding capture (`settle_funding`, PRODUCT_SPEC §3.3 signs over the whole settlements elapsed) and a `close_paper` path (`OPEN→CLOSING→CLOSED`) that flattens both legs with reduce-only/sell-owned fills and records realized PnL (funding + trading PnL − fees); each `PositionLeg` now carries its mark price, per-interval funding rate, and interval. `funding-arb-execution-service` adds `ExecutionService::close`, `PositionsRepo::update`, and a `PositionDto::to_domain` reload (values round-trip through `f64`; lossless decimal persistence deferred to the ledger slice). The API adds RBAC-gated, state-idempotent `POST /api/v1/positions/{id}/close` (already-closed → `200`, non-open → `409`). Published as OpenAPI/`@ayenisholah/perpeto-api-client` **0.6.0** (`closePosition`; `Position.funding_captured/realized_pnl/closed_at`, `PositionLeg.mark_price/funding_rate/funding_interval_hours`). Paper-only: re-hedge, auto-exit triggers, and partial-fill/unknown-outcome recovery remain deferred.
- M2 Slice 3 — paper position open lifecycle. `funding-arb-domain` gains a `position` module: an open-path state machine (PRODUCT_SPEC §5.2 `QUALIFIED→RESERVED→OPENING→OPEN|OPEN_FAILED`) and a deterministic `open_paper` simulator that sizes both legs from a ranked `Opportunity`, records order intents and simulated taker fills with deterministic client order ids, and gates residual (unmatched) delta against a new §6.2 unmatched-exposure cap added to `RiskLimits`. A new `funding-arb-execution-service` crate opens positions (`ExecutionService::open`, reusing the deterministic scanner and fixtures — no schema change to opportunities) and persists them (`PositionsRepo`, `0005_paper_positions.sql`). The API adds RBAC-gated `POST /api/v1/positions` (OWNER/TRADER only; `Idempotency-Key`-deduplicated), `GET /api/v1/positions`, and `GET /api/v1/positions/{id}`. Published as OpenAPI/`@ayenisholah/perpeto-api-client` **0.5.0**. Paper-only and network-free: funding capture, close, re-hedge, partial-fill/unknown-outcome recovery, and circuit breakers remain deferred to Slice 4.
- M2 Slice 2 — opportunity detail, full filters, and risk reservations. `funding-arb-domain` gains a `risk` module (`RiskLimits` §6.2 safe-starter defaults + `RiskAssessment`) used as scanner eligibility gates and per-opportunity paper reservations, and richer `Opportunity` fields (break-even funding, required capital, entry basis, leverage, funding direction, per-leg forecast). The API adds the full §4.6 filter/sort set on `GET /api/v1/opportunities`, plus `GET /api/v1/opportunities/{route_id}` and `GET /api/v1/risk/limits`; opportunities persist as a serialized payload (`0004_opportunity_detail_risk.sql`). Published as OpenAPI/`@ayenisholah/perpeto-api-client` **0.4.0**. Live position/order reservations and circuit breakers remain deferred to the execution slice.
- M2 Slice 1 — deterministic paper opportunity scanner. `funding-arb-domain` gains `market`/`forecast`/`opportunity` modules (venues, funding observations, a transparent non-ML funding forecaster, and PRODUCT_SPEC §4.5 opportunity ranking with eligibility gates) using `rust_decimal`. A new `funding-arb-scanner-service` crate loads embedded market fixtures, ranks two-leg routes, and persists snapshots (`0003_market_scan.sql`); the `engine` binary runs it on an interval. The API adds a read-only, RBAC-gated `GET /api/v1/opportunities` (with `route_type`/`venue`/`min_net_apr`/`min_probability` filters), published as OpenAPI/`@ayenisholah/perpeto-api-client` **0.3.0**. Paper-only and network-free: no venue connectors, credentials, or execution.

### Security

- Staging deployment validates paper mode and uses a pinned SSH host key; runtime trading secrets remain outside GitHub Actions.
- Provider identity is keyed by immutable subject rather than email; access is pending by default, refresh credentials are device-bound/rotating, and retained deletion evidence uses an audit pseudonym.

### Fixed

- Applied canonical Rust formatting and completed the M0 OpenAPI metadata, response, and explicit public-health security declarations required by contract linting.

### Changed

- Rebranded Signex to **Perpeto**: renamed the `SIGNEX_*` runtime environment variables to `PERPETO_*`, the public API origin to `https://api.perpeto.xyz`, the Postgres role/database to `perpeto`, and the published contract package to `@ayenisholah/perpeto-api-client`. The Apple audience `com.signex.mobile` and the `signex://` OAuth redirect scheme are unchanged. Deployments must update `runtime.env` (new variable names, `DATABASE_URL`) and rename the database in lockstep — see `docs/DEPLOYMENT.md`.
- Moved project-control documentation under `docs/` and recorded the temporary solo-maintainer administrator bypass policy.
- Hardened the versioned API client to reject incompatible health payloads and verify compiled code and schemas before publication.
- Isolated the paper staging API on host loopback port 8081, aligned PostgreSQL staging with the specification-pinned 18.4 image digest and data layout, and made deployment wait for dependency health.
